KiCad‑iOS · Display & Input

Desktop windows, tablet input.

KiCad is a desktop program: real windows, real menus, a mouse-first canvas. The window layer is rebuilt for the tablet, and the tablet's input — touch, gestures, external displays, hardware keyboards — is wired into KiCad's own machinery. Everything on this page is part of the shipped build, verified in the shipped binary by the release gates.

/ Windows

A titlebar on every window

Every window — manager, editors, dialogs — carries a titlebar strip at the top: the window's title on the left, then the Cursor toggle, Minimize and Close on the right, in Windows order. In frames the strip sits above the real menu bar in space the layout reserves; nothing is overlaid and no control is covered. The floating pill of the Spike builds is retired.

Drag by the titlebar

The strip is the drag surface. A press that moves past a small threshold drags the window — including a maximised editor, which un-maximises and follows — and a press that doesn't is a tap on the buttons. Minimize docks the window to a strip at the left edge; a tap on the dock restores it, titlebar and all.

Full screen, desktop scale

Windows open filling the screen — no black bands. The interface lays out at desktop-monitor scale, at 150% of the panel's raw pixel grid for readability. The app declares a real launch screen and full-screen presentation, and frames maximise on open regardless of geometry persisted by older builds.

Every window fits its display

Every top-level window and dialog is clamped to the available area of the display it is actually on — asked from the display at runtime. No resolution is hardcoded anywhere in the port, so the same clamp follows an external display. Oversized dialogs — Preferences is the worst offender — open with their OK and Close buttons on screen. Content whose own minimum is wider than the panel can still clip inside a window that fits; the window itself always fits and stays closable.

Smoother moves

Dragging used to repaint the world per mouse sample: every size event forced a full canvas buffer realloc and redraw, and each touch sample arrived twice. The canvas resize is deferred until the size settles — a burst becomes one redraw at the final size, at full quality — and drag moves are coalesced to the latest position. Final geometry is identical; the churn in between is gone.

/ Touch

Pinch zoom, both editors

Spread two fingers on the canvas and the view zooms in — smoothly and continuously, anchored at the pinch centre, through KiCad's own SetScale view machinery. Not a bitmap stretch. The Schematic Editor and the PCB Editor both gain it from the same canvas code, and the release gate proves the gesture path in the shared canvas library both editors link.

Two-finger pan

Two fingers down together, dragged without changing their spacing, pan the sheet or the board through KiCad's own SetCenter. One-finger behaviour is untouched: a one-finger drag still selects and drags exactly as KiCad defines it — no accidental pans.

Optional virtual cursor

For precise canvas work there is an on-screen cursor, and it is an option: the Cursor toggle on every titlebar turns it on, it is off by default, and the setting is remembered. One finger drags anywhere and the arrow moves relatively, trackpad-style; lift the finger and the click lands at the arrow. Two-finger gestures are never captured by the cursor — pinch keeps zooming with the cursor on.

/ Keyboard & mouse

KiCad is shortcut-driven, so the bridge carries hardware keyboards and mice completely. Four paths in the translation layer do their full job: the char-hook event KiCad's tool dispatcher and dialogs depend on is generated, so dialog undo/redo, Escape handling and grid tricks see keys first, and Alt+letter/digit hotkeys arrive with their real key codes (Alt+1 lands as Alt+1, not '¡'); Shift+Tab moves focus backwards; the keypad Enter confirms like Enter; and the wheel handler keeps pixel deltas, so scroll-wheel zoom at the pointer is smooth. Modifier mapping matches KiCad's bindings: the physical ⌘ key arrives as the Control modifier KiCad's shortcuts are written against. Right-click context menus and hover tracking ride the same bridge.

/ External display

Extended, not mirrored

Connect a USB-C/HDMI display or an AirPlay screen and an Ext button appears on every titlebar. Tap it and that window moves to the external display and fills it — maximised at that display's own native size, asked at runtime — while the iPad keeps its own windows. That is extension, not mirroring: the window's view is assigned to the external screen's own window, which is the platform's designed path. Tap Ext on any iPad-side titlebar to bring the window back, or unplug — a disconnect returns it on its own. Modal dialogs are never moved.

Stated plainly: the Ext control ships at the platform layer and is verified in the shipped binary. How much pointer and keyboard input iPadOS routes to a window living on an external screen is the open item — the feature is labelled partial until a device answers it.
