KiCad‑iOS · Unofficial Port

KiCad runs on iPad. The real KiCad.

This is a port of the actual upstream KiCad 10.0.1 — its own source code, its own windows, its own buttons — compiled for iPadOS. Not a recreation. Not a lookalike. It installs on a real iPad, completes KiCad's first-run wizard, and opens the KiCad project manager. The current release, v13, carries KiCad's complete stock libraries inside the bundle, fixes the root cause that kept the editor modules from loading in v11, and rebuilds the floating window control inside the window — as the handle that drags it.

/ What this is

KiCad is the world's leading open-source electronics design suite — schematic capture, PCB layout, and a family of companion tools driven from one project manager. It ships on Windows, macOS and Linux. Now it runs on the iPad too. Launch the app and KiCad's project manager stands up: the real menu bar, the Project Files tree, the launcher column with the real colour icons, and the tool descriptions — in KiCad's light desktop appearance, driven by touch, Apple Pencil, keyboard and mouse.

/ What works today

Every item here is verified — the launch chain on a real iPad, the rest by the automated gates every build passes before it ships. Where a card rests on the gates, it says so.

✓Builds end to end

The whole of KiCad 10.0.1 compiles and links for iOS arm64 — 1,591 of 1,591 build steps: the manager, every editor module, and the supporting libraries.

✓Installs and launches

The unsigned IPA sideloads onto an M‑series iPad and opens. Signing, the iOS entry point, and the first paint all check out on hardware.

✓First-run wizard completes

KiCad's genuine setup wizard is walkable from the first page to the last — its navigation renders, its pages advance, setup finishes.

✓The manager stands up

Real menus, real icons, the project tree and the description pane — the same manager window KiCad opens on the desktop.

✓Python is in

KiCad's embedded Python ships whole: the CPython standard library, the compiled pcbnew module, stock scripting plugins and footprint wizards, plus the PCBWay and JLCPCB addons from the official PCM index.

✓Files are reachable

File sharing is on. Projects live in the app's Documents folder and move on and off the iPad the normal way.

✓Stock libraries ship in the box

KiCad 10.0.1's libraries, complete: 222 symbol libraries and 155 footprint libraries, the default library tables resolving straight to them, plus 19 project templates and the demo projects. The build gates prove the tables resolve; on device, v11's setup did not find the defaults — the fix is compiled into the current release and its on-device pass runs next.

✓The manager, audited

Every menu opens, every item acts, every button does its real job — checked control by control. Tools that launched separate programs on the desktop — Gerber viewer, calculator, converters, page-layout editor — open inside the app, and the image converter carries its module.

✓A floating window control

Rebuilt in v13: the Minimize/Close bar lives inside the current window as an overlay — manager, editor, or dialog — instead of floating as a separate window iOS layering could bury (v11's device pass never saw that design). Drag the bar and the window moves with it; minimize still docks the window to the left edge and a tap restores it. Shipped and gate-verified — the gate proves the installer call in the shipped binary; the on-device pass runs next. Windows stay clamped inside the screen.

/ How it's built

KiCad was never written for iOS. Four walls stand between its source and a tablet, and the port answers each one with working machinery:

1

The wxQt bridge

KiCad's interface is written in wxWidgets, which has no iOS port. Here it runs on wxWidgets' Qt backend — wx 3.3 over Qt 6.9.3 — and Qt runs natively on iOS. KiCad's own build system already recognises the Qt port of wx.

2

Single-process Kiway

On the desktop, KiCad's editors run as separate processes. iOS apps are single-process, so each editor ships as a kiface module loaded inside the one app process, opening as its own window.

3

Embedded Python

KiCad's build requires Python, and its scripting is part of the program. A full CPython 3.13 sysroot is cross-compiled for iOS and embedded in the app, so Python initialises at startup and import pcbnew resolves to the real compiled module.

4

A canvas that fits the platform

The desktop canvas is OpenGL; iOS offers no OpenGL. KiCad's built-in Cairo software canvas carries the editors on iPad — correct rendering on the platform's own terms.

One of everything, verified before it ships

The bundle carries exactly one libpng, one zlib and one expat, shared by every component — and the build fails closed if a bundled duplicate tries to sneak back in. Every package passes automated gates before release: full symbol-closure audit across all images, Qt resource checks, the libpng unity gate, a content gate proving the bundled libraries and editor modules ship complete in the bundle, and deep signing verification. New in v12, a binary-inspection gate reads the shipped executable itself and proves the port's code is actually compiled in — the check that would have caught v11's miss; run against v11, it fails on every count. In v13 the same gate also proves the floating-controls installer call is present in the shipped executable. A build that fails a gate does not ship.

/ Current status

Build v13 is the current release. It carries v12's fix for the root cause that v11's on-device pass (2026‑11‑07) exposed: a build switch that three of the port's patches depend on sat on the wrong library target, so those patches were never compiled into v10 or v11 at all — a fact proven from the shipped v11 binary itself. On top of that, v13 rebuilds the floating window control inside the window and makes it the window's drag handle. The launch chain underneath is device-proven (v10, 2026‑11‑06); beyond it, nothing in v12 or v13 is device-proven yet. v13's on-device pass is the immediate next step.

  • ProvenThe launch chain. Install → sign → launch → Python initialises → wizard completes → the manager window stands. Every link in that chain is demonstrated on hardware (v10).
  • Shipped in v13The window controls, rebuilt. The floating Minimize/Close bar no longer floats as a separate window: that construction could be buried by iOS window layering, and v11's on-device pass never saw the bar. In v13 the bar is a child overlay re-parented into whichever window is current — the manager, an editor frame, or the modal dialog itself — and it is the window's drag handle: drag it and the window moves with it, with a small movement threshold keeping taps and drags apart. Minimize still docks the window into a strip at the left edge — 84 pt wide, stacking, Stage Manager style — and a tap restores it. Shipped and gate-verified: the binary gate proves the installer call in the shipped executable. The on-device pass runs next.
  • Shipped in v12The root cause, fixed. With the build switch set on the correct target, the editor-module search fix and the stock-library location fix are compiled in and active for real. The editor modules also sit at the bundle root — a belt-and-braces copy in the exact location the app asks for first — and a startup repair re-points library tables inherited from the broken builds, so an upgrade lands on the bundled defaults without redoing setup. A new gate inspects the shipped binary and verifies all of it; against v11 it fails on every count.
  • Shipped in v11Stock libraries in the bundle. KiCad 10.0.1's libraries ship complete — 222 symbol libraries and 155 footprint libraries — with the default library tables resolving to them, plus 19 project templates and the demo projects. The build gates prove the tables resolve; v11's setup did not find the defaults on device — the fix is compiled into the current release and its on-device pass runs next.
  • Shipped in v11A fully working manager screen. Every menu opens, every item acts, every button does its real job — audited control by control. Tools that launched separate programs on the desktop open inside the app, and the image converter carries its module.
  • Stated plainlyNo titlebar dragging. Windows do not drag by their titlebars: Qt's iOS layer draws no titlebar and provides no system window move. In v13 the floating bar is the handle instead — drag it and the window follows. Windows are clamped inside the visible screen area.

v13's on-device pass runs next: clean startup with no load dialogs, each editor open, the wizard's library step served from the bundled defaults, the bar present inside the window and dragging it. The full change ledger for the port lives in the repository's MODIFICATIONS.md.

/ Install

Builds are produced by the repository's Spike workflow as unsigned .ipa files (≈263 MB — the stock libraries ride along). The install is a standard sideload:

  1. Download the .ipa artifact from a workflow run in the repository.
  2. Sideload it with a signer such as Signulous, or your own signing setup.
  3. Launch KiCad (spike). The first-run wizard walks through setup, and the project manager opens behind it.

Requirements: an M‑series iPad running iPadOS 17 or later.
